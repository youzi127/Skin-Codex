# 复杂背景下的文字可读性

## 目标

让正文在浅色、深色和高纹理背景上可读，同时保留背景的沉浸感。先确认绘制层与文字实际占用矩形；不要把“看不清”直接等同于需要加白色面板。

## 决策顺序

1. **背景安全区**：把人物、黑色轮廓和高纹理主体避开正文高频区域；这是首选。
2. **路由级阅读层**：在聊天阅读侧使用低透明、方向性渐变，向主体侧渐隐；不要整页铺同色蒙层。
3. **内容级纱雾**：仅当局部内容仍跨越深色或高纹理元素时，使用 `.skin-codex-message-content` 的伪元素置于文字后方。纱雾无边框、无固定圆角、`pointer-events: none`，并以轻微模糊软化边缘。
4. **功能表面**：输入框、菜单、代码块和工具卡可以使用更稳定的实体/半实体表面；它们属于操作区。

## 参数原则

- 颜色、透明度、混合方式和模糊半径由当前主题的背景亮度、色温、纹理密度推导；不要复制上一主题的数值。
- 固定白纱不是默认方案：在深色背景上会形成突兀白块。优先用与主题表面接近的低透明色、渐变或混合模式；深色主题也可使用低透明深色纱层来压低亮纹理。
- 不用文字描边、重阴影或发光代替背景对比层；它们会降低正文清晰度并显得廉价。
- 不给每条消息增加边框、圆角卡片或明显色块。内容层纱雾必须看起来像环境光，而不是 UI 容器。

## 验证

1. 在浅色、深色和高纹理区域各检查一段用户消息与一段助手消息。
2. 用 CDP 记录 `.skin-codex-message-content` 与其 `::before` 的矩形、`background`、`filter`、`z-index` 和 `pointer-events`。
3. 检查长消息、代码块、工具卡、滚动中段和窄窗口；确认纱雾不扩展为整行横带，也不遮挡交互。
4. 若固定纱雾在某一背景上明显可见，回到背景安全区或采用主题适配的混合/色调方案；不要继续叠加白色透明度。
